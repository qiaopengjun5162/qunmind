# 微信日报视觉蓝图

这份文档回答的不是“今天封面怎么画”，而是：

- 为什么 `QunMind` 的公众号日报视觉不该继续漂
- 哪些视觉决策应该固定
- 哪些能力可以借鉴外部项目，但不能直接塞进主进程

当前参考启发之一是 [helloianneo/ian-handdrawn-ppt](https://github.com/helloianneo/ian-handdrawn-ppt)。它最值得借鉴的不是“手绘风格”本身，而是先做内容 intake、叙事规划、页面 archetype 和 visual DNA，再去渲染最终画面的工作流。

## 目标

为个人公众号 `寻月隐君` 的固定栏目 `AI · Web3 最新日报` 建立一套稳定视觉配方，让读者形成以下预期：

- 一眼认出这是同一栏目，而不是每天换皮
- 首屏就知道重点在哪里，而不是信息堆叠
- 封面、正文、链接区有明确层级，不会互相抢注意力
- 即使以后引入外部图像生成，也不会反过来破坏日报主链路

## 设计原则

### 1. 视觉先服务于辨识度，不先服务于变化感

日报属于固定栏目，不是一次性专题页。对这类内容，稳定比“每次都不一样”更重要。

固定项应包括：

- 栏目标题：`AI · Web3 最新日报`
- 账号署名：`寻月隐君`
- 主体气质：克制、专业、轻科技感
- 封面基调：浅底 + 深色标题，避免白字低对比
- 正文主主题：`theme: notebook`

可变化项应只承载“今天不同在哪里”，例如：

- `digest`
- 导语
- 今日焦点
- 焦点相关的轻量副标题或辅助短句

### 2. 先做叙事蓝图，再做视觉输出

视觉不应从“选颜色、加图标”开始，而应从内容结构开始。

当前公众号日报更适合固定为以下叙事顺序：

1. 导语：告诉读者今天为什么值得看
2. 今日三件事：建立首屏导航
3. 今日焦点：给出唯一优先阅读入口
4. AI / Web3 / 技术、产业与政策：正文分区
5. 推荐深读：给出真正值得跳转的长材料
6. 资料索引：留存完整追溯入口
7. 继续交流：固定收口

这意味着后续所有视觉优化都必须围绕这条阅读路径，而不是单独优化某个卡片。

### 3. 视觉 DNA 要少而稳定

从日报长期运营角度看，最怕“每次都多改一点，最后谁也认不出来”。

视觉 DNA 应尽量少：

- 1 套固定封面母版
- 1 套固定正文主题
- 2 到 3 个固定信息块 archetype

当前已经稳定的 archetype：

- `intro`：导语 / 收束
- `summary`：首屏速览
- `callout`：今日焦点
- `compact-links`：资料索引

后续即使再试新样式，也应优先在这几个 archetype 内微调，而不是频繁发明新 block。

### 4. “图像生成”只能是辅助渲染层，不是主链路

`ian-handdrawn-ppt` 这类项目适合启发未来的封面或配图工作流，但不适合直接并进 `QunMind` 主进程。

原因很简单：

- `QunMind` 的主职责是素材选择、成稿和发布
- 图像生成属于高波动、强审美、强人工复核的后处理环节
- 一旦把图像生成塞进主链路，日报稳定性会再次被视觉实验绑架

正确边界应是：

- `QunMind` 输出稳定正文与结构化视觉提示
- 外部 renderer / skill / 设计工作流负责生成封面或配图
- 只有被人工确认的视觉结果才进入发布链路

## 当前栏目视觉配方

### 封面

当前封面应继续保持：

- 浅色背景
- 深绿色或深墨色主标题
- 个人技术笔记气质，而不是媒体热榜气质
- 不靠夸张 3D、霓虹、赛博荧光去制造“AI 感”

封面想表达的不是“今天所有内容”，而是：

- 这是固定栏目
- 作者是 `寻月隐君`
- 主题是 AI / Web3 / 科技信息筛选

所以封面上不要继续堆太多副标题、热词和临时话题词。

### 正文

正文的核心视觉目标不是“花”，而是“读者知道先看哪”。

固定要求：

- 导语只负责定调，不承担过多信息
- `今日三件事` 是首屏导航，不要写成长段
- `今日焦点` 必须是唯一最强阅读入口
- 正文卡片和资料索引必须明显区分
- 链接区用更轻、更紧凑的版式，避免喧宾夺主

### 资料区

资料索引的目的不是展示“我们搜了很多”，而是保证可追溯。

因此资料区视觉原则应是：

- 小字号
- 单行优先
- 完整 URL 必须存在
- 不与正文卡片争主视觉位

## 借鉴 `ian-handdrawn-ppt` 的正确方式

适合借鉴的层：

- intake：先看今天的主题、焦点、受众
- narrative planning：先确定“先看什么、再看什么”
- page archetype：固定不同信息块的视觉角色
- visual DNA：把颜色、线条、结构和氛围固定下来
- contact sheet：未来如果批量出视觉稿，先统一预览再人工选

不适合直接借鉴的层：

- 把整个手绘讲解风格直接套进公众号日报正文
- 让主进程自己负责生成大批量视觉页面
- 把每日报视觉目标做成“完全重设计”

## 推荐工作流

如果未来继续优化日报视觉，建议固定成这条链路：

1. 日报正文先稳定生成
2. 从正文提取结构化视觉 brief
3. 在外部视觉工具里生成候选封面 / 配图
4. 人工挑选最终稿
5. 记录来源、输出文件和备注到 `docs/visual-operations.md`
6. 再进入 `moonpub` 发布链路

这里的关键是：视觉结果必须服从正文，而不是反过来逼正文去配图。

## 非目标

这份文档当前不主张：

- 重做一套新的公众号主题系统
- 把 `moonpub` 变成视觉设计器
- 把外部图像生成当成日报成功与否的前置条件
- 让每期日报都长得完全不同

## 结论

对 `QunMind` 来说，`ian-handdrawn-ppt` 最有价值的启发不是“生成一张更花的图”，而是提醒我们把日报视觉收口成：

- 固定栏目身份
- 固定叙事顺序
- 固定视觉 DNA
- 可选的外部渲染层

只有这样，日报的封面和排版优化才会越做越稳，而不是越改越像一次性实验。
